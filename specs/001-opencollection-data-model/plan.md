# Implementation Plan: OpenCollection Canonical Data Model

**Branch**: `001-opencollection-data-model` | **Date**: 2026-11-07 | **Spec**: [specs/001-opencollection-data-model/spec.md](spec.md)

**Input**: Feature specification from `/specs/001-opencollection-data-model/spec.md`

## Summary

Refactor Clapi's underlying data storage model so that **OpenCollection v1.0.0** becomes the canonical format for collections, folders, HTTP requests, environments, variables, and authentication settings. Encapsulate file persistence behind an extensible `CollectionStorageDriver` (supporting bundled documents for the initial delivery per FR-034), preserve non-HTTP MCP data in OpenCollection's official `extensions.clapi` block, strictly separate persisted documents from transient UI/runtime state, and provide an automated, idempotent migration engine that upgrades legacy Clapi collections without data loss.

## Technical Context

**Language/Version**: Kotlin 2.1.21 (JVM / Kotlin Multiplatform desktop target)

**Primary Dependencies**:
- `org.jetbrains.kotlinx:kotlinx-serialization-json:1.8.1`
- `com.charleskorn.kaml:kaml:0.67.0` (YAML serialization engine on top of kotlinx.serialization)
- `com.networknt:json-schema-validator:1.5.1` (RFC / Draft-07 official JSON schema validation)
- `io.ktor:ktor-client-*` 3.1.2
- `org.jetbrains.kotlinx:kotlinx-coroutines-core:1.10.2`
- `org.jetbrains.compose` 1.8.1
- `io.insert-koin:koin-core:4.0.2`

**Storage**:
- Primary Collection Storage: OpenCollection v1.0.0 bundled document files (`.json` or `.yaml`) managed by `CollectionStorageDriver`
- Local Secrets & State: `PlatformStorage` (`clapi.workspace`, `clapi.tabs`, `clapi.history`, local secrets vault)

**Testing**:
- `org.jetbrains.kotlin:kotlin-test` & `junit:junit:4.13.2`
- Ktor embedded Netty server & CIO client for end-to-end regression tests (`SampleCollectionE2ETest`)
- Schema conformance test suites using `../../scratch/Clapi`

**Target Platform**: Desktop JVM (Linux, macOS, Windows)

**Project Type**: Desktop application (Compose Multiplatform multi-module architecture)

**Performance Goals**:
- Deserialization & validation: < 50ms for typical collections (up to 200 items); < 500ms for large collections (10MB+)
- Memory: Zero retention of completed response/request stream buffers in persisted collection graphs

**Constraints**:
- **FR-001 / FR-005**: 100% compliance with official OpenCollection v1.0.0 JSON schema
- **FR-010**: A folder is never an HTTP request (`OpenCollectionItem` sealed hierarchy)
- **FR-017**: Secret variable values must never appear in serialized shared outputs, logs, or debug traces
- **FR-022 / FR-023**: MCP data isolated in `extensions.clapi.mcp` and never stored as HTTP requests
- **FR-024**: Strict separation between persisted document models and runtime execution/UI states
- **FR-029 / FR-030**: Migration must be non-destructive (backup created prior to writing), validated before saving, and idempotent

**Scale/Scope**:
- Architectural data model migration affecting `core-model`, `core-storage`, `core-network`, `feature-requests`, and `ui-shared`

    └── LegacyMigrationE2ETest.kt             # Ingestion & migration tests for legacy fixtures

**Structure Decision**: Multi-module Kotlin architecture preserving core boundaries:
- `core-model` owns pure data structures.
- `core-storage` owns serialization, schema validation, persistence drivers, and migration.
- `feature-requests` / `core-network` owns execution transformation.
- `ui-shared` manages UI binding and workspace coordination without leaking filesystem details.
