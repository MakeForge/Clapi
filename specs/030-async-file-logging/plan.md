# Implementation Plan: Asynchronous Persistent File & Diagnostics Logging

**Branch**: `030-async-file-logging` | **Date**: 2026-11-18 | **Spec**: [specs/030-async-file-logging/spec.md](spec.md)

**Input**: Feature specification from `/specs/030-async-file-logging/spec.md`

## Summary

Implement an enterprise-grade, non-blocking asynchronous logging subsystem for Clapi using **Tinylog 2** (`tinylog-api`, `tinylog-impl`, `slf4j-tinylog`) as the underlying logging engine and **SLF4J / `kotlin-logging`** as the application facade. The system guarantees zero UI thread and coroutine blocking via Tinylog's background writing thread (`writingthread = true`), provides persistent rolling file storage in `<storageDir>/logs/clapi.log` with daily and 10MB size rotation plus gzip compression, safely isolates `stdout` in headless `--mcp` mode by directing console output to `stderr`, and bridges events into Clapi's in-app bottom diagnostics panel via a custom `ServiceLoader` writer.

## Technical Context

**Language/Version**: Kotlin 2.1.21 / JVM 17+  
**Primary Dependencies**:
- `org.tinylog:tinylog-api:2.8.1`
- `org.tinylog:tinylog-impl:2.8.1`
- `org.tinylog:slf4j-tinylog:2.8.1`
- `org.slf4j:slf4j-api:2.0.17`
- `io.github.oshai:kotlin-logging:8.0.7`  
**Storage**: Rolling file logs stored at `<storageDir>/logs/clapi.log` (rotating daily or at 10 MB, 5 archives retained, compressed with gzip)  
**Testing**: JUnit 4 / Kotlin Test (`:ui-desktop:desktopTest`, `:ui-shared:desktopTest`), Roborazzi UI tests  
**Target Platform**: Desktop JVM (Linux, macOS, Windows)  
**Project Type**: Desktop GUI (Compose Multiplatform) + Headless CLI / MCP server (`--mcp`)  
**Performance Goals**:
- 0 ms blocking on main/UI thread (EDT) or network coroutines during log emission
- < 0.05 ms caller-thread overhead per log statement
- Sustains bursts of 1,000+ log events/sec while maintaining stable 60 FPS animation/scrolling  
**Constraints**:
- Maximum 60 MB total disk footprint for log files
- 100% clean `stdout` in headless `--mcp` mode (no log leakage into JSON-RPC stdio protocol)  
**Scale/Scope**: ~10 modified/new source files, 1 resource configuration file, 1 SPI registration, comprehensive unit and benchmark tests  

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Zero UI Blocking**: Tinylog's lock-free ring buffer and asynchronous `writingthread` ensure all disk writing and string formatting occur off the UI thread. *PASSED.*
- **Persistent Auditability**: Logs survive app restarts and capture unhandled JVM crashes via `Thread.setDefaultUncaughtExceptionHandler`. *PASSED.*
- **Protocol Safety**: In headless Stdio mode (`--mcp`), `writer1.stream = err` ensures `stdout` is exclusively preserved for JSON-RPC 2.0 frames. *PASSED.*
- **Backwards Compatibility**: Existing `state.log(...)`, `state.logNetworkEvent(...)`, and `NetworkLogger` interfaces remain fully supported and delegate directly to the SLF4J facade. *PASSED.*

## Complexity Tracking

| Violation / Consideration | Why Needed | Simpler Alternative Rejected Because |
| :--- | :--- | :--- |
| Custom `org.tinylog.writers.Writer` | Allows real-time live log inspection inside Clapi's in-app bottom panel without disk re-reading | Polling disk files or tailing log files from the UI incurs significant disk I/O and latency |
| Uncaught Exception Handler | Ensures fatal crashes and coroutine panics are recorded before the JVM process dies | Without an uncaught exception handler, fatal crashes only print to stderr and are lost if the terminal isn't attached |
